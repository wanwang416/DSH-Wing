## 一、卡点重查结论（M44-2「removed=1 但 dispose=0」）

### 1.1 阿深指出的矛盾成立，真因比预判更直接

原诊断（fake timers 下 `Date.now()` 固定 → `<` 边界不满足）**自相矛盾**，已废弃：
若 `idleAt < cutoff` 不成立，该记录根本不进清理分支，`removed` 必为 0；实际 `removed=1`，说明清理分支完整跑通。

**实读实现（先读实现，不猜）**：

- `src/session/mapper.ts:144-158` `空闲清理()`： victims 循环里 `agents.delete → idleAt.delete → bumpGeneration → await opts.disposeAgent?.(handle).catch(...)`（**第 156 行**，走的是 **deps 回调**，不是 `handle.dispose`）；
- 生产接线 `src/index.ts:600`：`async disposeAgent(handle) { await handle.dispose(); }` —— **实现无缺陷**，handle.dispose 是由生产装配的回调间接调用的。

**真因**：测试夹具（`tests/stage7a-hygiene.test.ts` 原 195-197 行）的 `createSessionMapper({...})` **根本没传 `disposeAgent`**。可选回调缺省 → `opts.disposeAgent?.()` 恒 undefined → 永不调用 → `h1.dispose` 恒 0 次。这与 `removed=1`（逻辑跑通）**同时成立、互不自洽缺失**——断言盯错了对象。

### 1.2 处理：改夹具，不改实现，保留 removed=1 断言

按阿深处理要求第 2 条第一分支：实现调 `deps.disposeAgent` 而夹具没串 → **改夹具**：

```ts
const mapper = createSessionMapper({
  createAgent: async (chatId: string) => (chatId === "oc_1" ? h1 : h2),
  // ★ M44-2 卡点修正（7a 验收）：实现走 opts.disposeAgent 回调（mapper.ts:156），
  //   handle.dispose 由生产接线（index.ts:600）在回调内调用——夹具不注入时
  //   h1.dispose 恒 0 次恰与 removed=1 自洽。断言必须盯住真正的调用点。
  disposeAgent: (h) => h.dispose(),
});
```

- `removed=1` 断言**原样保留**（证明清理分支跑通）；
- `h1.dispose` 调用 1 次断言保留（经注入的回调真实传导到 handle）。
